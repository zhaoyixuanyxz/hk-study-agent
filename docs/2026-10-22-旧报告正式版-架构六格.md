# 架构六格：旧报告正式版与自动抓取

写这一页之前的三个判定：采集是定时批处理，报告过期与重生成是一次请求结束的读写，都不算可恢复的长流程。没有人点名编排引擎。港校官网 HTTP 和持久化存储是外部端口；模型本轮不跨边界去调抓取，因此不新增 MCP。

## 1. 编排

自己写循环。

采集是已有批处理脚本按调度反复跑完一轮，失败重跑整轮或按已有 feed 记录跳过，不等人审批，不从中途某一步接着做人机长流程。报告打上抓取日期、把旧分享标过期、重新生成，都是一次请求结束。不写 LangGraph，不写 Temporal。

操作者口径：学费和截止日期以月为新鲜度单位；抓取全自动，不以操作者手工跑脚本当正常路径。调度频率只要能让正式版用到的学费和截止日期的抓取日期落在最近一个自然月内。现有每日脚本可以继续当这个循环的入口，但不能靠人手调试来凑记录。

## 2. 工具边界

这次不涉及 MCP。

外部端口：

- 港校官网学费页和截止日期页（HTTP 抓取）
- 持久化存储（情报条目、采集批次、报告、分享令牌、画像快照）
- 触发批处理的调度器（机器定时，不是操作者终端）

留在进程里：把 `tuition` / `deadline` 抽成可数条目、把 `fetchedAt` 写进报告、判断画像或情报是否比报告新、把旧分享从正式版拿掉。

适配器怎么接、调度器装在哪，交给软件实现。本页不定。

## 3. 状态

对话和建档进度仍用现有会话与画像存储，本页不改对话编排。

本页要读回的状态：

- 每条学费、每条截止日期的 `fetchedAt`，以及该次采集批次是否完成
- 报告生成时所依据的画像快照与引用的情报条目
- 分享是否仍算正式版（过期与人手关闭是两件事，人手关闭保持现有「链接无效」）

批处理不是可恢复长流程，中断后不从半轮进度接着做；下一轮从调度器再跑，以存储里的采集批次记录为准。没有连续、自动留下的完成记录，就还没有可引用的抓取日期，不能先改报告文案。

## 4. 可靠性

交给后续 SLO 的目标（本页只点名，不定错误预算）：

- 正式版报告里每一条学费、每一条截止日期的抓取日期，都不早于最近一个自然月
- 采集由调度器自动跑；操作者不上机调试，也能在存储里看到完成的采集批次
- 画像或引用情报一变，旧分享链接不再作为正式版；只有重新生成的报告可以发出去

失败时重跑整轮批处理。不要求从上次成功的一条 feed 恢复。

## 5. 安全

信任边界：学生登录区、公开分享页、出站抓取港校官网。

要防的资产：

- 报告和画像里的个人申请信息
- 分享令牌（过期后不得再当正式版；人手关闭后不得重新打开）
- 出站抓取不得把内网或密钥带到官网请求里

家长本轮不加账号，只读学生发出的同一份链接。过期规则对家长和学生对齐。
