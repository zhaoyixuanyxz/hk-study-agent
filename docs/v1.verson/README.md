# V1：留学规划交付与情报版文档入口

本目录是 V1 版本的研发决策入口与 **发布前文档归档入口**（V1-P6），用于替代 MVP 阶段的 Phase 0-5 关单型文档。

V1 的核心目标是将当前跑通型 MVP 升级为可对外试用的产品版本：通过六个 tab 完成专业建档、可信档案、申请策略、正式报告、交付物管理和香港留学情报知识库。

**自动化守门**：`cd backend && npm run test:v1-p6`；手测见 [V1-主链路QA用例.md](V1-主链路QA用例.md)。

## V1 六个业务 Tab

| Tab | 产品职责 |
|-----|----------|
| Chat | 专业建档顾问，回答短、准、专业，帮助用户补齐关键信息 |
| Profile | 可信申请档案，展示已确认事实、待确认事实、冲突和缺失项 |
| Plan | 申请策略页，解释冲刺、匹配、保底、预算、风险和时间线依据 |
| Report | 正式交付报告，支持在线查看、PDF 下载、公开链接分享 |
| History | 交付物中心，管理历史报告、版本、分享状态和下载入口 |
| Intelligence | 香港留学情报知识库，提供院校/专业情报、来源链接、时间线、搜索和提醒 |

## 阶段划分

| Phase | 名称 |

| V1-P0 | 范围冻结与架构基线 |
| V1-P1 | Chat 专业建档顾问 |

| V1-P3 | Report 与 History 交付产品化 |
| V1-P4 | Intelligence 数据底座 |
| V1-P5 | Intelligence 产品体验与 AI 引用 |
| V1-P6 | 全链路 QA 与上线准备 |

## 使用建议

1. 产品和研发先共同评审 [V1-开发路线清单.md](V1-开发路线清单.md)，确认范围和阶段边界。
2. 进入排期时使用 [V1-具体任务完成清单.md](V1-具体任务完成清单.md)，按 Phase 拆分任务。
3. 每个 Phase 结束后，对照路线清单中的阶段验收标准进行验收。
4. MVP 旧文档只作为历史参考，不再作为 V1 的主决策入口。
