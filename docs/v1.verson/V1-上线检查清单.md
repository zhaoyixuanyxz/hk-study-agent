# V1 上线检查清单

在对外试用或小流量发布前逐项确认（**P0** 必须；**P1** 建议）。

---

## 1. 环境与配置（P0）

| 项 | 说明 |
|----|------|
| `DEEPSEEK_API_KEY` | 生产填真实密钥；留空则为 Mock LLM，仅适用于内测 |
| `PDF_DISABLED` | CI / 无浏览器环境设 `1`；生产需 PDF 时必须不设且保证 Chromium 可用 |
| `PUPPETEER_EXECUTABLE_PATH` | 可选：显式指定 Chrome/Chromium 路径 |
| `CORS_ORIGINS` | 包含正式前端源（逗号分隔），含协议与端口 |
| 数据路径 | `backend` 启动时 JSON 数据文件路径可写、已备份策略 |

---

## 2. 安全与合规（P0）

| 项 | 说明 |
|----|------|
| 私有 API | 均需 `Authorization: Bearer`（除注册、登录、健康检查、公开分享 GET） |
| 公开分享 | 仅返回单份报告 HTML；关闭分享后立即 404（见自动化 `test:v1-p6`） |
| 限流 | 可选 `APP_RATE_LIMIT_MAX`（每分钟每 IP 最大请求数，0 表示关闭） |

---

## 3. 情报任务（P1）

| 项 | 说明 |
|----|------|
| `INTELLIGENCE_FETCH` | 生产若开启真实抓取，需保证出站网络与白名单维护 |
| `INTELLIGENCE_LINK_CHECK` | 验收用抽样；常态可关以免拖慢 CI |
| 定时任务 | 计划任务调用 `cd backend && npm run intelligence:daily`（或等价 `node` 调用），失败告警 |

---

## 4. 域名与分享（P0）

| 项 | 说明 |
|----|------|
| 分享链接 | `url_path` 为相对路径 `/api/v1/public/reports/...`；前端或网关需使用**用户可访问的同一主机名**拼接或通过反向代理统一域名 |
| HTTPS | 生产强烈建议全站 HTTPS，避免 token 与报告泄露 |

---

## 5. 发布前验证命令

```bash
cd backend && npm run test:v1-p6
cd ../frontend && npm test
```

可选（本机有 Chromium）：不设 `PDF_DISABLED` 时执行 `cd backend && npm run test:v1-p3-pdf-e2e`。
