## 1. 六 Tab 职责与边界

| Tab | 产品职责（做什么） | 输入 / 输出概要 | 非职责边界（本 Tab 不单独承担） |
|-----|-------------------|-----------------|--------------------------------|
| **Chat** | 专业建档顾问：短、准、专业，补齐关键画像信息 | 入：用户自然语言；出：结构化对话、建档状态与缺口提示 | 不负责长文正式报告排版与 PDF |
| **Profile** | **可信申请档案**：已确认事实、推断、待确认、冲突与缺失项 | 入：对话与确认操作；出：档案视图与状态标签 | 不负责生成梯度选校策略全文（由 Plan 承担） |
| **Plan** | **申请策略页**：冲刺 / 匹配 / 保底及依据、预算、风险、时间线 | 入：就绪画像；出：可解释策略卡片 | 不做多方案并排对比器（V1 不做项） |
| **Report** | **正式交付报告**：短、准、专业且通俗；在线阅读 | 入：方案与画像；出： HTML 报告 | 不负责情报全文托管（外链至来源） |
| **History** | **交付物中心**：报告版本、分享状态、下载入口、历史回看 | 入：用户操作；出：列表与元数据 | 不做支付与订单 |
| **Intelligence** | **香港留学情报知识库**：院校 / 专业情报、来源、时间线、搜索与站内提醒 | 入：采集与审核流水线；出：可被引用的条目与检索 API | 不替代各校官网权威解释；不外发强打扰推送 |

**Tab 重叠控制原则**：建档与事实归属以 Profile 为准；策略依据集中在 Plan；凡引用 Intelligence 事实，须在对应界面或输出中可追溯**来源链接**。

## 3. 分 Tab 可测验收标准

以下每条均可通过「用例步骤 + 期望结果」在后续 Phase 验收；**每个 Tab 至少 3 条**。

### 3.1 Chat

#### 可测验收标准

1. 任一助手回复可被判定为包含「判断、原因、下一步」三类信息（或等价结构），不出现无依据断言。
2. 单轮最多追问 **1～2** 个关键问题；超出则视为不合规（可在自动化或抽检中抽样消息计数）。
3. 用户输入已满足阈值时，系统给出**明确短诊断**，而非继续堆砌通用追问话术。
4. 当助手引用 Intelligence 条目中的事实时，同屏或结构化字段中可出现**可追溯来源标识**（链接或标题 + URL）。
5. 页面可展示**建档进度**或等效摘要（维度完成度或可读摘要）。
6. 页面可区分**事实待确认 / 报告是否可生成**等状态之一（或与 Profile 一致的聚合提示）。

### 3.2 Profile

#### 可测验收标准

1. 至少一类事实可被标记为：**用户已确认**、**系统推断**、**待确认**、**冲突**之一，且互不混淆。
2. 对任一**缺失维度**，能说清**影响哪类产出**（仅方案 / 仅报告 / 两者）。
3. 关键事实可回溯到来源类型（对话抽取 / 用户显式确认等）中的至少一种展示。
4. 档案分区（学术、语言、目标、预算、时间线等）在信息架构上可导航，且无与 Plan 重复的冗长策略正文。
5. 与 orchestration（流程状态）一致性：不会在「不应进入方案」的状态下误标「档案已全部确认」。
6. 任一 API 或页面展示的档案 JSON 可被自动化快照测试覆盖（对齐 `profile-snapshot` 等契约）。

### 3.3 Plan

#### 可测验收标准

1. 冲刺 / 匹配 / 保底三类卡片均具备**可被理解的依据说明**（非仅校名列表）。
2. **预算 / 风险提示**可被普通用户读完并复述范围级结论（不一定要精确币种预测）。
3. **时间线**：能说明当前时间节点是否紧迫及建议的下一步动作类型。
4. 若引用情报库事实，须展示来源或引用块（标题 + 链接或与 citation 模型的映射）。
5. 在跳转或生成 Report 前有**就绪或缺口检查**，避免半成品进入正式报告而未提示。
6. 未登录或非资源所有者访问他人 `planId` 时返回 **401/404**，无数据泄露。

### 3.4 Report

#### 可测验收标准

1. 报告**无硬性字数下限**；验收以「决策者 3～5 分钟读懂核心结论」为抽检口径而非字数。
2. 支持**在线浏览**既有 HTML 段落与结构锚点。
3. 正式版支持 **PDF 下载**（V1-P3）；文件可被打开且无整体不可读错乱。
4. 支持生成**公开长随机分享链接**，分享页无需登录可读被分享的那份报告。
5. 支持**关闭分享**后旧链接失效（403/404）。
6. 分享页显著位置含**隐私提示**（包含个人申请信息）。
7. 引用情报处列出**来源列表**或与正文脚注一致的结构化引用区。

### 3.5 History

#### 可测验收标准

1. 列表可区分多版报告：**生成时间 / 标识最新版**的规则明确。
2. 每条有可辨识的分享状态：**未分享 / 已分享 / 已关闭**（或等价枚举）。
3. 历史条目提供 **PDF 再次下载**（与对应报告版本绑定）。
4. 列表摘要含：生成时间、关联方案标识、引用情报条数或可折叠摘要之一。
5. 仅资源所有者可枚举与下载本人历史；他人 Token 探测返回 **401/404**。

### 3.6 Intelligence

#### 可测验收标准

1. 情报条目必含：**来源类型**（官方 / 权威媒体 / 教育平台）、**原文或可访问链接**、**发布时间（或抓取时间层级）**。
2. **中文摘要**默认展示且可切换查看原文摘要或跳转原文。
3. 支持混合搜索：**关键词 + 结构化筛选**（院校 / 学位 / 专业 / 年份 / 信息类型等子集）。
4. 仪表盘或首页具备：**个性化更新区、院校入口、重要变更、搜索入口** 四类能力中的可测组合（P5 完整实现）。
5. 院校详情为「**院校概览 + 最新情报 + 时间线**」结构的可导航页面。
6. Chat / Plan / Report 任一使用知识库断言时：**无来源则不允许作为事实写入**（接口或中间层校验可测）。
7. 站内提醒：**关注对象或与画像相关的更新**可出现在站内面板；无站外强制推送验收项。

## 4. Intelligence 独立子系统（架构约束）

情报能力在数据管线、可信度与检索上与「对话建档」并列，须满足：

- 独立数据来源与条目存储（条目、来源注册表、审核状态）。
- Chat / Profile / Plan / Report **仅通过**既定检索与 `citation` 契约消费情报；不直接耦合爬虫细节。
- 对外产品入口为 **Intelligence Tab** 与子页面；对内为独立 API（见 `V1-API-草案.md`）。

## 5. 用户路径（Mermaid）

### 5.1 建档到交付

```mermaid
flowchart LR
  startNode[登录或注册]
  chatTab[Chat 建档对话]
  profileTab[Profile 确认档案]
  planTab[Plan 申请策略]
  reportTab[Report 正式报告]
  historyTab[History 交付物]

  startNode --> chatTab
  chatTab --> profileTab
  profileTab --> planTab
  planTab --> reportTab
  reportTab --> historyTab
```

### 5.2 情报与 AI 引用

```mermaid
flowchart LR
  intelHome[Intelligence 首页]
  intelSearch[搜索与筛选]
  intelSchool[院校详情与时间线]
  consumeTab[Chat 或 Plan 或 Report]

  intelHome --> intelSearch
  intelSearch --> intelSchool
  intelSchool --> consumeTab
  intelTab[Intelligence Tab] -.-> intelHome
```

## 7. 与实现对齐说明（V1-P6 收口）

以下能力已在当前代码库落地，与本规格一致；更细的接口与运维见 [V1-API-草案.md](V1-API-草案.md)、[V1-上线检查清单.md](V1-上线检查清单.md)、[V1-P6-发布说明.md](V1-P6-发布说明.md)。

| 能力 | 说明 |
|------|------|
| 六 Tab | `Chat` / `Profile` / `Plan` / `Report` / `History` / `Intelligence` 均可从主导航进入并完成主路径。 |
| Intelligence | 仪表盘、院校墙与详情、关键词检索、结构化筛选、AI 摘要（含 citations）、关注与站内提醒、导航徽标；列表与卡片使用 `textContent` 展示标题/摘要以降低注入风险。 |
| 报告交付 | HTML 报告、PDF（可选 `PDF_DISABLED`）、公开分享链接与关闭分享、历史列表中的分享状态与统计。 |
| 引用 | Chat / Plan / Report 使用情报时经后端与情报条目对齐校验 citations；无有效来源的事实不写入输出。 |
| 不做项 | 仍不包含多方案对比、支付、顾问后台、自动递交等（见 §2）。 |
