# V1 数据模型草案

**版本**：v1.0  
**持久化**：MVP 为 JSON 文件 [`backend/src/store.js`](../../backend/src/store.js)：`migrateDb` 顶层数组与对象；V1 **优先在原 db 结构中扩展并列数组**，必要时再迁移至真正 DB。

---

## 1. 现有 MVP 顶层集合（保持）

| 集合 key | 用途 |
|-----------|------|
| `users` | 账号、token、邮箱、密码哈希 |
| `threads` | 会话、orchestration 状态 |
| `messages` | 对话消息 |
| `profileMemories` | 画像抽取记忆片段 |
| `conversationSummaries` | 会话摘要 |
| `profileSnapshots` | 结构化画像快照 |
| `semanticMemoryChunks` | 语义检索 chunk |
| `planResults` | 方案结构化结果 |
| `reportResults` | 报告内容与元数据 |
| `analyticsEvents` | 埋点 |

## 2. 报告交付扩展（草案）

挂载在每条 `reportResults[]` 或平行 `reportShares[]`——二选一以实现简单为准。

### 2.1 `reportResults` 建议新增字段（对象内）

| 字段 | 类型 | 说明 |
|------|------|------|
| `version` | `number`（可选） | 单调递增，便于 History |
| `pdfAssetId` | `string \| null` | 生成的 PDF 句柄（若仅存路径或对象存储 key） |
| `generatedAt` | `string` ISO | 可与现有 createdAt 对齐或替代 |
| `planIdRef` | `string \| null` | 溯源方案 |
| `citationRefs` | `array` | `{ itemId, title, url, publishedAt }` 摘要数组 |

### 2.2 分享：`reportShares[]`（新集合，推荐）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | `string` | 主键 |
| `reportId` | `string` | FK 逻辑指向 report |
| `userId` | `string` | 所有者 |
| `shareToken` | `string` | 长随机，公开访问 |
| `status` | `enum` | `active` \| `revoked` |
| `createdAt` / `revokedAt` | `string` | |
| `viewCount` / `lastViewedAt` | `number` / `string` | V1-P3 访问统计可选 |

兼容性：不改变现有匿名 GET `/reports/:reportId` 行为；仅有 share token 可走公共路由。

## 3. Intelligence（新集合）

### 3.1 `intelligenceSources[]`（来源注册表）

| 字段 | 说明 |
|------|------|
| `id`, `name`, `baseUrl`, `tier` (`official` \| `media` \| `platform`) |
| `trustRules`（可选 JSON） | 自动发布 / 强制审核 |

### 3.2 `intelligenceItems[]`（条目）

对齐路线：标题、摘要、适用对象、来源类型、发布时间、原文链接、院校、学位、专业、信息类型、中文译文、归档 ID 等。

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | `string` | |
| `sourceId` | `string` | 外键 |
| `reviewStatus` | `enum` | `auto_published` \| `pending_review` \| `approved` \| `rejected` |
| `locale` | `object` | `titleZh`, `summaryZh`, `titleOriginal`, `snippetOriginal` |
| `canonicalUrl` | `string` | 原文链接 |
| `publishedAt` / `fetchedAt` | `string` | |
| `schoolIds` / `programTags` | `array` | 筛选与院校页 |
| `infoType` | `string` | 截止日期 / 学费 / 录取要求 / 政策 … |
| `dedupeHash` | `string` | 去重 |
| `sensitiveHint`（可选） | `array` | 学费、截止日期等高敏标记 |

### 3.3 `intelligenceTimelineEvents[]`（可选独立表或与 item 嵌入）

关联 `schoolId`（或 programme），年份窗 2023–2026，`itemIdRef`，`effectiveDate`。

### 3.4 `userFollows[]`（关注）

| 字段 | 说明 |
|------|------|
| `id`, `userId`, `targetType` (`school` \| `program_area`), `targetId`, `createdAt` |

## 4. 引用模型 `Citation`（逻辑结构，可多处置）

嵌入在 AI 输出或独立 `citations[]`：

```json
{
  "itemId": "string",
  "sourceTitle": "string",
  "url": "string",
  "publishedAt": "string",
  "quoteOrSummary": "string"
}
```

无 `url` 或 `itemId` 的规则型事实不得在 Chat / Plan / Report 中标记为「已引用情报」。

---

## 5. 迁移注意事项

1. **`migrateDb`**：为每个新数组添加 `if (!Array.isArray(db.xxx)) db.xxx = []`。
2. 先 **append-only** 扩展，避免破坏性重命名 `reportResults` 已有字段。
3. 真正 DB 迁移时：以本文实体为语义源，导出脚本按 userId / reportId 分片。
