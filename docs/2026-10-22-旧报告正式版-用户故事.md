# User Stories: 旧报告不再当作正式版

对照 [2026-10-22-旧报告正式版-prd.md](./2026-10-22-旧报告正式版-prd.md)。四条都是 P0。体量是粗分，不是估点。不排实现顺序，依赖只记在每条里。

---

## Story 1: 正式版上的逐条抓取日期

### Story Header

| Field | Value |
|-------|-------|
| ID | US-1 |
| Title | 正式版上的逐条抓取日期 |
| Persona | 已登录学生 |
| Priority | P0 |
| Epic/Feature | 旧报告不再当作正式版 |
| Estimate | 中 |

### User Story Statement

**As a** 已登录学生,

**I want** 在正式版报告上看到每一条学费和每一条截止日期的抓取日期,

**so that** 我能判断这份还能不能发给家长。

### Context & Background

假设要求报告上的日期能回对到情报，页脚免责不算。正式版打开当日，日期须落在往前 31 个自然日内。没有抓取日期的数字不能写成正式事实。见 PRD FR-4、FR-5、FR-6、FR-7。

### Acceptance Criteria

#### AC-1: 逐条可见

**Given** 一份正式版报告，其中学费条数与截止日期条数都能指回带 `fetchedAt` 的情报条目

**When** 学生打开这份正式版

**Then** 每一条旁边都有抓取日期，且等于该条 `fetchedAt` 的日历日，或该次完成批次 `finishedAt` 的日历日

#### AC-2: 页脚不算

**Given** 报告只有页脚或免责里的一句「数据可能变化」或单独的院校发布时间，正文条目旁没有抓取日期

**When** 学生核对学费和截止日期

**Then** AC-1 判失败

#### AC-3: 没有抓取记录就不是正式数字

**Given** 某条学费或截止日期没有可回对的 `fetchedAt`

**When** 生成或打开正式版

**Then** 该条不作为正式数字出现，也不编造一个日期

#### AC-4: 不超过一个月

**Given** 学生在日期 D 打开正式版

**When** 查看其中每一条仍作为正式数字出现的学费和截止日期

**Then** 该条抓取日期落在 D 往前 31 个自然日之内（含 D）

#### AC-5: 门禁未过不改文案

**Given** US-4 的 7 日自动完成记录尚未齐

**When** 准备在报告上加上抓取日期或「数据截至」句子

**Then** 报告文案保持原样

### Design Notes

- 日期贴在该条学费或截止日期旁边，不集中放在文末。
- 不改图表区块。

### Technical Notes

- 日期必须指回情报条目或该次完成批次。编排仍是自己写循环，不新增 MCP。
- 不在本故事里规定改哪个源文件。

### Dependencies

| Dependency | Type | Status |
|------------|------|--------|
| US-4 的 7 日自动完成记录 | 故事 | 未过则 AC-5 挡住文案 |

### Out of Scope

- 过期与重新生成（US-3）
- 家长账号
- 用页脚免责代替逐条日期

### Open Questions

无。

## Story 2: 家长看到的不是过期正式版

### Story Header

| Field | Value |
|-------|-------|
| ID | US-2 |
| Title | 家长看到的不是过期正式版 |
| Persona | 阅读分享链接的家长 |
| Priority | P0 |
| Epic/Feature | 旧报告不再当作正式版 |
| Estimate | 小 |

### User Story Statement

**As a** 阅读分享链接的家长,

**I want** 打开学生发来的链接时能分辨它还是不是正式版,

**so that** 我不会拿过期报告去做申请判断。

### Context & Background

家长没有账号，看的是学生发出的同一份链接。过期和人手关闭是两件事。见 PRD FR-9、FR-10。

### Acceptance Criteria

#### AC-1: 过期链接不是正式版

**Given** 家长持有学生发出的分享链接，且该报告已按 US-3 过期

**When** 家长打开链接

**Then** 页面表明这不是正式版，不能当作仍有效的申请报告来读

#### AC-2: 仍有效时与学生看到同一份日期

**Given** 链接仍是正式版，且报告满足 US-1

**When** 家长打开链接

**Then** 看到与学生同一份逐条抓取日期，不要求家长登录

#### AC-3: 人手关闭仍然无效

**Given** 学生已关闭分享

**When** 家长打开原链接

**Then** 页面是现有的「已关闭或无效」，不是一份报告正文

#### AC-4: 关闭后不得因过期规则重新打开

**Given** 链接已经人手关闭，之后画像或情报又发生了会使报告过期的变化

**When** 家长打开原链接

**Then** 仍然是关闭/无效，链接不会重新变成可阅读页面

### Design Notes

- 不新增家长登录，不新增账号切换。
- 过期页和「已关闭或无效」页要能区分：前者是这份报告已过期，后者是链接已关闭。

### Technical Notes

- 公开页仍含个人申请信息；过期后不得继续当正式版传播。
- 不改变现有关闭分享的无效结果。

### Dependencies

| Dependency | Type | Status |
|------------|------|--------|
| US-3 过期规则 | 故事 | AC-1 需要已过期的链接 |
| US-1 逐条日期 | 故事 | AC-2 需要正式版上已有日期 |

### Out of Scope

- 家长账号
- 代写文书、提交申请

### Open Questions

无。

## Story 3: 变更之后必须重新生成才能再发

### Story Header

| Field | Value |
|-------|-------|
| ID | US-3 |
| Title | 变更之后必须重新生成才能再发 |
| Persona | 已登录学生 |
| Priority | P0 |
| Epic/Feature | 旧报告不再当作正式版 |
| Estimate | 中 |

### User Story Statement

**As a** 已登录学生,

**I want** 画像或院校情报一变，旧报告就过期，重新生成之后才能再发出去,

**so that** 家长拿到的正式版对得上现在的画像和情报。

### Context & Background

画像变更和引用情报变更是同一条规则。只改列表上的「最新」标记、旧链接仍返回原正式 HTML，不算过期。标本只打情报更新；画像必须走同一条规则。见 PRD FR-8、FR-9、FR-11、FR-12。

### Acceptance Criteria

#### AC-1: 情报一变就过期

**Given** 一份已分享的正式版，引用了某条学费或截止日期

**When** 该条情报更新

**Then** 原分享链接不再是正式版

#### AC-2: 画像一变同样过期

**Given** 一份已分享的正式版，引用的情报没有变

**When** 学生画像变更

**Then** 原正式版同样过期

#### AC-3: 未重生成不能当正式版发出

**Given** 报告已过期，学生尚未重新生成

**When** 学生或家长打开原分享链接

**Then** 该链接不能当作正式版发出去

#### AC-4: 只有新报告是正式版

**Given** 报告已过期

**When** 学生重新生成报告

**Then** 只有新报告可以当作正式版发出；旧份可以留在历史里看，但不是正式版

#### AC-5: 只改「最新」标记不算过期

**Given** 情报或画像已变

**When** 列表把另一份标成最新，但原链接仍返回原来的正式报告 HTML

**Then** 本故事判失败

### Design Notes

- 学生在过期后能看出要重新生成才能再发。
- 不改授课型硕士聊天边界。

### Technical Notes

- 过期与人手关闭分开。本故事不把已关闭链接重新打开。
- 判断「比报告新」用报告生成时记下的画像快照和引用条目。不在本故事里指定存储实现。

### Dependencies

| Dependency | Type | Status |
|------------|------|--------|
| 报告生成时记下的画像快照与引用条目 | 数据 | 没有记号就无法判断「变了」 |
| US-1 | 故事 | 新的正式版仍须满足逐条日期 |

### Out of Scope

- 7 日采集门禁（US-4）
- 图表、家长账号、香港以外

### Open Questions

无。

## Story 4: 采集自动跑，手工调试不算

### Story Header

| Field | Value |
|-------|-------|
| ID | US-4 |
| Title | 采集自动跑，手工调试不算 |
| Persona | 已登录学生 |
| Priority | P0 |
| Epic/Feature | 旧报告不再当作正式版 |
| Estimate | 中 |

### User Story Statement

**As a** 已登录学生,

**I want** 学费和截止日期由调度自动更新，而不是等人手工跑脚本,

**so that** 正式版上的数字是最近一个月内抓到的，不靠一次调试。

### Context & Background

操作者口径：以月为新鲜度单位，全自动抓取。PRD 仍要求在改报告文案之前，先看到连续 7 日的自动完成记录；这 7 日证明调度在跑，不把新鲜度改成「必须每天一条新学费」。见 PRD FR-1、FR-2、FR-3。

### Acceptance Criteria

#### AC-1: 调度器触发并留下批次

**Given** 没有人在终端执行采集

**When** 到达一次机器调度

**Then** 跑完一轮，并留下一条批次：状态为完成或失败，且有 `finishedAt`

#### AC-2: 失败不算完成

**Given** 一轮采集失败

**When** 查看该次批次

**Then** 状态为失败；不得把该次记成完成，也不得据此把报告上的日期改成当天

#### AC-3: 七日门禁只数自动批次

**Given** 以核对日为终点，向前 7 个自然日

**When** 核对该日之前能否改报告文案

**Then** 每一日都至少有一条调度器留下的完成批次才算通过；缺一日、记录为空、或只有手工执行的批次，都算未通过

#### AC-4: 手工跑不充当正常路径

**Given** 操作者在终端手工执行了一次采集

**When** 用这次记录声称「全自动正在跑」或把它计入 AC-3

**Then** 不计入，报告文案仍按 AC-3 未通过处理

### Design Notes

- 学生界面不提供「替我现在抓一次」来充当正式版新鲜度。

### Technical Notes

- 自己写循环。失败重跑整轮，不从半轮某一条接着爬。
- 调度器装在哪不在本故事决定。现有按日脚本可以当入口，但正常路径必须是机器触发。
- 不新增 MCP。

### Dependencies

| Dependency | Type | Status |
|------------|------|--------|
| 无其他故事 | — | 本条先于报告文案（US-1 AC-5） |

### Out of Scope

- 错误预算和 SLO 数字
- 操作者日常手工采集
- 从失败的半轮接着爬

### Open Questions

无。
