## 1. MVP In Scope（本期必须交付）

| 能力 | 说明 |
|------|------|
| 账号 | 注册、登录、退出；用户数据按账号隔离 |
| 智能对话建档 | 开放式自然语言多轮对话，非固定问卷为首发路径 |
| 对话中断恢复 | 关闭页面或离开后再次进入可续聊、可加载历史 |
| 动态用户画像 | 对话沉淀为可查看的画像摘要、待补充、更新时间等 |
| 单套方案生成 | 基于画像快照生成 1 套含冲刺/匹配/保底的申请方案 |
| HTML 报告 | 在线查看，七章结构与字数等按 MVP 验收 |
| 历史记录 | 可回看对话、画像快照、方案、报告（与账号绑定） |
| 基础埋点与上线验收 | 关键行为可统计；试运行前检查单可执行 |

**原则声明**：首发实现路径为「自然语言对话建档」，**不以固定问卷作为 MVP 首发实现路径**（可与对话能力并存或后置，但不得替代对话为主路径）。

## 3. 需求变更规则

### 3.1 变更分级

| 级别 | 含义 | 处理 |
|------|------|------|
| **A 类（冻结项）** | 影响架构分叉或大范围返工 | 需产品+研发+AI 评审，更新基线文档并记录决策 |
| **B 类** | 影响接口契约或 Phase 2–3 实现 | 需接口/契约评审，更新对应 Phase 0 交付物 |
| **C 类** | 文案、展示顺序、非契约字段说明 | 产品确认后可进入对应阶段迭代 |

**默认列为 A 类的高敏感项**：

- `planInputView` 与画像快照的概念结构（字段集、必填规则）
- MVP 五页范围与核心用户主路径
- 单 Agent / 事实确认 / 生成门槛等 AI 基线（见技术路线文档）

### 3.2 变更记录模板

每条变更建议记录：

| 字段 | 说明 |
|------|------|
| 变更 ID | 如 CHG-YYYYMMDD-序号 |
| 提出日期 | |
| 变更项 | 改什么 |
| 原因 | 业务或技术原因 |
| 影响阶段 | Phase 1–5 中哪些受影响 |
| 决策人 | |
| 结论 | 采纳 / 暂缓 / 拒绝 |
| 关联文档更新 | 列出需改的文件名 |

## 4. 成功指标与可测口径（草案）

以下为 Phase 0 与后续试运行观测用的**指标定义草案**；实际数据来源在 Phase 1 起随埋点与日志落地后校准。

| 指标 | 定义 | 数据来源（目标态） | 统计方式（建议） |
|------|------|-------------------|-------------------|
| 对话建档完成率 | 用户在一次会话中达到「可进入方案生成前」就绪状态的比例（就绪定义与 `readiness` 一致） | 埋点：会话开始、readiness 达成或会话结束 | 达成会话数 / 有效开始会话数，周期内滚动 |
| 方案生成成功率 | 在画像与门槛满足前提下，方案生成接口返回成功的比例 | 方案生成 API 结果 + 前端结果展示 | 成功次数 / 触发生成次数 |
| 报告生成成功率 | 触发生成报告且用户可打开完整七章报告的比例 | 报告任务状态 + 报告详情访问 | 成功次数 / 触发次数 |
| 会话恢复成功率 | 用户再次进入同一线程时可加载历史并继续对话的比例 | 恢复接口成功 + 首条后续消息发送成功 | 成功次数 / 尝试恢复次数 |

**观察周期**：试运行阶段按周或双周复盘；Phase 0 仅要求**每条指标有定义、有目标数据来源与统计方式**，不要求已接入真实埋点。
