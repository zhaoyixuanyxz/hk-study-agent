## 1. Agent 形态（冻结）

| 决策项 | MVP 结论 |
|--------|----------|
| 编排复杂度 | **单 Agent 主路径**：一个建档 Agent 承担主对话、追问与缺口表达；不建设完整多 Agent 运营编排平台 |
| 与架构文档关系 | 模块上仍保留 `DialogueOrchestrator`、`PromptStrategyLayer` 等划分，由编排器调用单 Agent，而非多 Agent 并行竞争 |
| 扩展性 | Phase 2+ 若需拆分能力，以**不破坏 Phase 0 契约**为前提另立版本说明 |

## 2. 温度与双链路原则

| 链路 | 温度策略（概念） | 职责 |
|------|------------------|------|
| **主对话** | 相对较高 | 自然表达、追问节奏、共情与引导、缺口说明 |
| **事实确认与结构化抽取** | 相对较低 | 关键事实摘要、待确认项、结构化写入画像前的约束 |

**原则**：高温度不得单独驱动「硬事实」落库；关键事实须经过确认链或明确标记为候选/待确认（与 [Phase0-画像快照与planInputView契约.md](Phase0-画像快照与planInputView契约.md) 一致）。

---

## 3. Prompt 分层策略（最小集）

与 [对话建档Prompt设计稿.md](对话建档Prompt设计稿.md) 对齐，MVP 至少区分以下层级（可配置、可版本化）：

| 层级 | 英文占位 | Phase 1 是否必须实现 |
|------|-----------|----------------------|
| 系统角色 | `system` | 是 |
| 对话风格 | `style` | 是 |
| 采集与主题 | `collection` | 是 |
| 事实确认 | `confirmation` | 是 |
| 生成门槛 / 就绪 | `readiness` | 是（与是否允许进入方案生成挂钩） |

**版本管理要求**：

- 每层 Prompt 须有版本标识（如标签或 Git 版本），支持回滚到上一稳定版本。
- Phase 0 定稿：采用分层配置方案，不要求 Phase 0 内完成工程实现，但 Phase 1 须按此结构落地。

---

## 4. 事实漂移控制

| 概念 | 定义 |
|------|------|
| **硬事实** | 用户明确陈述且经确认（或强规则抽取）的信息，可进入画像快照的稳定字段 |
| **洞察** | 模型推断的倾向、建议、可能性表述，**不得**默认写为录取承诺或不可变事实 |
| **待确认** | 关键字段尚未确认前，在画像与 `planInputView` 中显式标记 |

**阻断规则**：当 `readiness` 判定未满足方案生成最低要求时，**不允许**进入方案生成（具体门槛字段见画像与 `planInputView` 契约文档）。
