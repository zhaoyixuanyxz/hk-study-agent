# Phase 0：画像快照与 planInputView 概念契约

**版本**：v1.0  
**阶段**：Phase 0（概念层，非数据库字段级）  
**依据**：[MVP-开发路线确认稿.md](MVP-开发路线确认稿.md)、[智能对话建档系统架构设计.md](智能对话建档系统架构设计.md)  
**对应 Epic**：`P0-AI-02`

---

## 1. 画像快照（Profile Snapshot）

### 1.1 职责

- 画像快照是**下游只读**的稳定视图，供方案生成等模块消费。
- **不**直接绑定原始对话全文；对话全文由会话/消息存储负责。
- 每次有效更新可产生新版本，带**更新时间**。

### 1.2 概念字段（逻辑分组）

以下为概念层分组，具体 JSON/表结构在 Phase 2 实现时展开。

| 分组 | 含义 | 备注 |
|------|------|------|
| `summary` | 面向用户的画像摘要文案 | 可随对话迭代 |
| `structuredFacts` | 结构化事实键值 | 与确认状态关联 |
| `gaps` | 待补充信息列表 | 驱动追问与 readiness |
| `insights` | 洞察与倾向 | 非硬承诺，与事实区分 |
| `confirmationState` | 关键事实的确认/待确认/冲突标记 | 与事实确认流一致 |
| `updatedAt` | 快照版本时间 | 必填语义 |

### 1.3 来源与可信度

| 来源类型 | 含义 | 能否直接进入 planInputView 硬输入 |
|----------|------|-------------------------------------|
| 用户确认事实 | 用户明确确认或强规则下的确认项 | 可 |
| 候选事实 | 模型提取待用户确认 | 需标记，默认不当作唯一依据 |
| 洞察 | 推断类信息 | 仅作辅助，不得单独支撑「录取概率」等承诺表述 |

## 2. planInputView（方案输入视图）

### 2.1 职责

- 从画像快照中派生出的、**方案生成引擎**所需的稳定输入结构。
- 目标：避免方案层直接解析自由文本或原始对话。

### 2.2 最小输入维度（概念）

| 维度 | 说明 | 典型内容 |
|------|------|----------|
| `academic` | 学术与标化相关 | 院校/专业背景、GPA、语言成绩等（以 PRD 为准） |
| `goals` | 目标方向 | 国家/地区偏好、专业意向、职业倾向 |
| `budget` | 预算 | 区间或可承受范围 |
| `timeline` | 时间窗口 | 入学意向、申请季 |
| `riskPreference` | 风险偏好 | 冲刺/稳妥倾向等（与方案三档策略一致） |

### 2.3 字段来源与必填策略

| 规则 | 说明 |
|------|------|
| 每个维度可标注 `source` | `confirmed` / `candidate` / `inferred` |
| 必填 | 方案生成**最低**所需维度在 Phase 2 与 `readiness` 对齐，本文档冻结**维度集合**；具体字段级必填在实现前由产品+AI 评审确认 |
| 待补充 | 缺失项进入 `gaps`，并阻断或降级方案生成（与 readiness 一致） |

### 2.4 与快照的关系

- `planInputView` **由**画像快照 + 规则/轻量映射**构建**（Phase 2 的 `planInputView` 构建服务）。
- 下游方案模块**只依赖** `planInputView` 与快照版本引用，不反向依赖原始对话。

## 3. 版本演进规则

| 规则 | 说明 |
|------|------|
| 兼容扩展 | Phase 2/3 可增加可选字段，**不得**删除或改变 Phase 0 已确认的基础维度语义 |
| 破坏性变更 | 若需重命名或合并基础维度，走 **A 类变更**（见 [Phase0-范围基线与变更规则.md](Phase0-范围基线与变更规则.md)） |
| 版本号 | 快照与 `planInputView` 均应有逻辑版本（如 `schemaVersion`），便于回放与排错 |
