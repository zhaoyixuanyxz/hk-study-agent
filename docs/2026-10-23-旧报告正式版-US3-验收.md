# US-3 验收：变更之后必须重新生成才能再发

对照 [2026-10-22-旧报告正式版-用户故事.md](./2026-10-22-旧报告正式版-用户故事.md) Story 3，以及已批准设计 [docs/superpowers/specs/2026-10-23-us3-report-expiry-design.md](./superpowers/specs/2026-10-23-us3-report-expiry-design.md)（Approach A：打开时现算；过期页无正文；不翻转 `share.enabled`）。

| AC | 结论 | 证据 |
|----|------|------|
| AC-1 情报一变就过期 | 通过 | `fetchedAt`/指纹变更或条目缺失 → `intel_changed`；公开分享集成测返回「报告已过期」、无正式正文 |
| AC-2 画像一变同样过期 | 通过 | 最新 `snapshotId` ≠ 报告 `snapshotId` → `profile_changed`；公开分享集成测过期页 |
| AC-3 未重生成不能当正式版发出 | 通过 | 过期公开链接只出过期页，不返回 `row.html`；与「已关闭或无效」文案可区分 |
| AC-4 只有新报告是正式版 | 通过 | 登录详情 stale 时仍可看正文且带 `freshness.fresh=false`（留着看）；公开旧 token 仍过期；新报告走既有 `appendReportResult` + 未变更时可正常分享（自动化覆盖旧链过期；重生后新链由实现路径保证） |
| AC-5 只改「最新」标记不算过期 | 通过 | 情报已变时另有更新报告标最新，原分享 token 仍过期页、不返回原正式 HTML |

**补充（故事技术注）：** 人手关闭优先——已撤销 token 仍走关闭/无效 404，不因情报变更重新打开。过期不改 `share.enabled`（Approach A）。

**验收通过。** 不改故事正文。下一步：回项目经理登记，派 US-2。
